# Fitme

A **single-user, self-hosted training plan generator and training log**. You run your own
instance; it serves you and nobody else. You use it through a Telegram bot and view plans and
progress on a small website.

> Plans are generated by AI. Fitme is not a trainer, coach, physiotherapist or medical
> service, and nothing it outputs is medical advice, diagnosis or treatment. If you have
> pain, dizziness, numbness or chest discomfort, stop training and talk to a doctor.

## What goes to the LLM provider

Generating or revising a plan sends a pseudonymized context to the configured LLM provider
(Anthropic by default): an internal user id, bucket values (experience, location, equipment,
...), flag codes, catalog exercise ids, numbers from your training log, and your own in-flow
free text (scrubbed of handles, emails, phone numbers and links first). It never sends your
Telegram id, chat id, name, or your screening notes. See
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §8.2 for the exact scope and its documented
limits.

## Quick start (Docker Compose)

Requires Docker with the Compose plugin.

```sh
git clone <this repo> fitme && cd fitme
cp .env.example .env
# edit .env: FITME_TELEGRAM_BOT_TOKEN, FITME_WEB_BASE_URL, FITME_SECRET_KEY,
# ANTHROPIC_API_KEY (or whichever provider key your model tiers use)
docker compose up -d
docker compose exec fitme fitme activate
```

Send the printed `/activate CODE` to your bot on Telegram, then `/start` to run setup.

`docker compose up` builds the image, applies database migrations automatically (the
entrypoint runs `fitme db upgrade` before `fitme serve`), and starts the bot + website in one
container. The website listens on `127.0.0.1:8080` on the host only — see **TLS** below to
expose it publicly.

## TLS

An optional `caddy` service (automatic HTTPS via Let's Encrypt) sits in front of `fitme`,
enabled with the `tls` Compose profile:

```sh
# in .env: set FITME_DOMAIN to your public hostname (matching FITME_WEB_BASE_URL's host),
# and FITME_FORWARDED_ALLOW_IPS=172.28.0.10 (Caddy's static address in compose.yaml, so
# uvicorn trusts X-Forwarded-* headers from Caddy only; never the whole subnet)
docker compose --profile tls up -d
```

This opens ports 80/443 on the host; without it, only `127.0.0.1:8080` is exposed and you're
expected to reach the site over SSH tunnel/VPN, or front it with your own reverse proxy.

## Backups and restore

`fitme backup --out DIR [--keep N]` (default `--keep 14`) writes an online, consistent copy
of the database via SQLite's own backup API — safe to run while the stack is up. From the
host:

```sh
./deploy/backup.sh   # docker compose exec -T fitme fitme backup --out /data/backups --keep 14
```

Wire it into cron for daily backups. See [`deploy/restore.md`](deploy/restore.md) to restore
one.

## Updating

```sh
git pull
docker compose up -d --build
```

Migrations run automatically on the next start; there's nothing else to do.

## Importing your history

If you already have a training log, import it once so the generated plans start from your
real loads instead of a calibration session. Write it as a TOML (or JSON) file following
[`docs/import-format.md`](docs/import-format.md): an alias table from your exercise names to
catalog ids, your past sessions with their sets, and optionally the plans you followed. Name
it `*.import.toml` (or `*.import.json`): those patterns are gitignored, since the file is your
health data. Then:

```sh
docker compose exec -T fitme fitme history import - < my.import.toml   # Docker
make import-history FILE=my.import.toml DRY=1                           # local dev: report only
make import-history FILE=my.import.toml                                 # local dev: import
```

The import is all-or-nothing per run, idempotent (importing the same file twice adds
nothing), and reports every session or plan it skipped and why. Imported loads become the
historical max the safety guards check against; the import itself never counts as a load
increase.

## Local development (without Docker)

Requires [`uv`](https://docs.astral.sh/uv/) and Python 3.13.

```sh
uv sync
cp .env.example .env   # edit it; the Makefile loads it automatically for these commands
make migrate
make serve
```

Run `make` with no arguments for the full command list, including `test`, `lint`,
`typecheck`, `catalog`, and `check` (lint + typecheck + catalog + test — run this before
committing).

## Makefile targets

| Target | Purpose |
|---|---|
| `install` | Install dependencies (incl. dev) into `.venv` |
| `lock` | Update `uv.lock` |
| `migrate` | Apply pending SQL migrations (local dev) |
| `serve` | Run bot + web + retention job (local dev) |
| `activate` | Print a one-time Telegram activation code (local dev) |
| `test` / `lint` / `fmt` / `typecheck` / `catalog` / `check` | Local dev QA |
| `export` / `delete` / `purge` | Data lifecycle (local dev; A§8.3/§8.4) |
| `unhold` / `hold-clear` | Clear open health holds (local dev; operator bypass) |
| `import-history` | Import past trainings/plans from `FILE=` (local dev; `DRY=1` to only report) |
| `llm-eval` | Run LLM eval fixtures against a real model (spends money; never run in CI) |
| `docker-build` | `docker compose build` |
| `up` / `down` | Start/stop the Docker Compose stack (`TLS=1 make up` for the `tls` profile) |
| `logs` | Follow the running container's logs |
| `backup` | Run a backup inside the running container |
| `activate-docker` | Print a one-time Telegram activation code (Docker deployment) |
| `unhold-docker` | Clear open health holds (Docker deployment) |
| `clean` | Remove local tool caches |
